# Matriks design system

Studio update: see [STUDIO_REDESIGN.md](STUDIO_REDESIGN.md) for the five-language adaptive shell, persisted presentation settings, solution modes and updated matrix contribution rendering. The timelines and single-controller invariants below still apply to guided playback; static steps and direct results do not wait for instructional intervals.

The interface is a mathematical workspace: the matrix, explanation, and next action take priority. The topic catalog uses aligned title, description, and operation columns on desktop, and wrapping rows on mobile. Color marks actions and mathematical roles, not arbitrary categories.

Typography uses the existing Flutter font stack, without a new font dependency. Headlines use 24–30 px, section titles 20 px, topic titles 16 px, body copy 14–16 px, and secondary labels 12 px. Body line heights are 1.4–1.5. Content width is capped at 1280 px. Spacing is primarily 8, 12, 16, 20, 24, and 48 px; corner radii are 8–20 px, with 24 px reserved for sheets. The theme's text theme also defines `labelLarge`/`labelMedium` styles, used for section labels such as the role legend and the details drawer's headings.

## Interaction rules

- Preserve visible native focus states and standard Tab traversal. Global shortcuts consume only recognized keys and respect focused controls.
- Numeric input accepts integers, decimals, and fractions; invalid entries receive a localized, cell-specific error. Calculation has a pending state and prevents duplicate submissions.
- Search combines with category filters and offers an explicit reset when no topics match.
- Use borders and restrained fills for instructional states; keep pivot/source/target labels so color is not the sole explanation. Row-operation highlights use two hues only: amber for the row being used (a heavier border and fill for the pivot, a thinner border for the source) and cyan for the row that changes (the target; a finished zero keeps its "0 ✓" badge, now in cyan). Purple and green no longer mark highlight roles; the augmented-matrix divider uses the neutral outline color. `RoleLegend` (in `widgets/step_card.dart`) sits under the matrix and shows only the roles the current step actually has, each with its own shape as well as its color.
- Button labels wrap at large text sizes. The editor scrolls on short screens. Wide transformation screens place the canvas beside controls.
- Button state changes use 120 ms; ordinary state feedback uses 180 ms; feedback panels use 220 ms. Reduced motion disables implicit interpolation where motion is used.
- Instructional time is linear and adapts to the operation: swaps 1200/1100/1700 ms, elimination and scaling 1500/3600/2400 ms with 1200 ms more operation time per changing column beyond three (columns where the source or scaled row holds 0 cannot change and are skipped), matrix addition 900/1300/1200 ms, the 2×2 adjugate 1400/2400/1800 ms, scaling a whole matrix 1500 ms + 900 ms per entry + 2000 ms, dot products and determinants 1500 ms preparation + 1400 ms per contribution + 2600 ms review. A determinant recap that only adds totals already shown counts as one contribution. Other steps use 1400/2200/2200 ms. Speed scales the complete timeline uniformly. Spatial easing is separate from reading time.
- Geometry is measured once per solution, so the matrix does not change size between steps. Cell text fades through (out, then in) rather than cross-fading. Entries of a sum or product not computed yet show a muted placeholder dot. Sarrus steps write the first two columns again beside the matrix so each product is a straight diagonal; finished diagonals stay faded. + products are green and − products red, as in the explanation.
- The decimal view is exact for values that terminate within four places; other values are rounded to four places and marked ≈, and nonzero values too small for that switch to scientific notation rather than showing 0.
- A finished lesson offers the result, a restart and the learner's own matrix. Static steps show no play button. Bottom navigation marks the selected destination with an indicator behind the icon and a bolder label.
- The transform canvas keeps a faint untransformed grid behind the moving one, fits the view to both animation endpoints, draws real eigenvector directions as dashed lines, uses the same colours as the basis labels, and turns the unit square red when orientation flips.
- Lesson navigation advances on the visible animation's completion, never on an independent periodic timer. Revision tokens reject stale completion callbacks. Manual navigation, scrubbing, replay, and arithmetic inspection stop automatic navigation.
- One primary play/pause control governs the active animation. The step-count button opens a named step list. A single collapsed `Details` drawer (`ExpansionTile`, key `operation-inspector`) holds the rationale ("Why this works"), per-cell calculations when the phase caption has none of its own, and the labeled progress slider with replay; it is titled "Details" when it has a rationale or calculations to show and "Inspect this operation" otherwise. Opening it pauses automatic progression. It starts expanded when the explanation level setting is "detailed".
- Reduced motion shows the final matrix, all three explanations, and all calculations; completion still waits for the reading interval. Backgrounding the app pauses playback.
- Cache discrete matrix-cell content per step and theme; rebuild the animation scene without rebuilding static math cells every frame. Keep caches bounded to the current step.
- Keypad and dimension controls have at least 44 px targets. Standard action buttons have a 48 px minimum. This is not a claim of comprehensive WCAG certification.
- Math text follows system text scaling. Wide values use horizontal scrolling rather than shrinking below the chosen type size. Repeated right-side row annotations are omitted; the operation formula remains above the matrix. Normal matrix cells are quiet, with role borders only where instructional meaning requires them. Player values adapt between 18 and 22 px using available layout width. During an operation, exact cell formulas fit down to a 14 px minimum (before system text scaling); results return to the normal size. Very long expressions remain scrollable. Guided operation cells reserve 120 px width and wide matrices follow the active column. Full calculation panels wrap at TeX operator boundaries.
- Below 600 px, use a single column. From 600–959 px, use flexible or scrolling layouts; the transform canvas can split in short landscape. The step player is one centred stage column (max width 880) at every screen width, never side-by-side; wide screens only get more padding around it. The matrix editor (`matrix_input`) and the transform visualizer still switch to side-by-side layouts from 960 px when text scale permits. Large text falls back to scrolling.
- Transform presets show selection; editing a coefficient sets Custom. The 2×2 coefficient grid supports direct decimal entry and steppers. Entries commit on Enter/blur; invalid drafts retain the previous valid transformation. The canvas transitions from its visible frame to the new target. Rotations preserve lengths when both endpoints are rotations; other intermediate frames are explicitly described as transitions. Basis vectors and target determinant are separately labeled. The target determinant is not rounded to one decimal, which could conceal small nonzero values.
- Show A’s source row and B’s source column above C during multiplication. Box each corresponding factor pair in sequence. Delay C’s result until all contributions are complete; avoid small canvas-drawn arithmetic labels.
- Phase explanations progressively reveal exact contributions; completed calculations remain available for inspection. The elimination rationale explains target ÷ pivot rather than duplicating the operation statement.
- Each step teaches one thing once. A step whose phase explanation already says what its description says hides the description; the solver's description, when shown, sits under the caption as a "why" note with a lightbulb icon and no header. Steps without a specific lesson show no source/operation/result placeholders. Per-cell calculation lists are hidden when the phase explanation already lists the same arithmetic. Role colours (pivot, source, target, zeroed) are used only where the step really has those roles, and the legend shows only roles present.
- The player's stage reads top to bottom: step title, an optional prediction card, the matrix (with its role legend), the phase caption, the "why" note, then the `Details` drawer. The caption (`InstructionExplanation`) is one sentence at a time that fades between phases, with three phase dots (key `phase-dots`) instead of a "1 / 3 · phase title" count; the phase name stays in the semantics label for screen readers. Lesson-complete and, when applicable, the eigen status and result checks follow after the last step.
- The player's app bar has one overflow menu (key `player-menu`, tooltip "More options") with "Show result", "Guided animation"/"Static steps" (checked items) and "Decimals" (checked), instead of three separate controls.
- The 2×2 inverse animates the adjugate (a and d swap places, b and c change sign) and then multiplies each entry by 1/det one at a time. LU eliminations show L beside U with the new multiplier framed and unwritten entries pending. Block inverses end on [I | A⁻¹] with the right block marked. Eigenvector steps name the matrix shown (A − λI).
- Catalog starter lessons use real worked examples. Quiz feedback addresses the selected misconception in both languages and preserves the scoring/navigation flow.
- The result screen and a finished lesson each show `ResultChecks` (key `result-checks`) when the operation has one: an independent exact-arithmetic confirmation (A·A⁻¹ = I; the determinant recomputed by the other kind of method; L·U = P·A; Ax = b for a unique system; rank + nullity = n; Av = λv for each exact eigenpair) with a held/failed icon and label. Sums, products and echelon forms show no check; a rounded eigenpair gets no check either. A 2×2 eigen result additionally offers "See it as a transformation" (`TransformLink`, key `transform-link`) on the result screen and the lesson-complete card, opening the transform visualizer on that matrix, when every entry is within [-1000, 1000].
- Settings groups the two choices most learners need — language/theme (Appearance) and predictions/reduced motion (Learning) — in view, and keeps solution mode, default speed, explanation level, number view and density inside a collapsed "More options" (`ExpansionTile`, key `more-settings`) whose defaults already suit a new learner. There is one brand action color; no accent-palette choice. The on-screen note says preferences and finished lessons stay on the device and that matrices and quiz answers are not saved. "Reset settings" restores display/playback defaults and keeps progress; "Reset progress" (shown only once there is progress) clears the last topic and finished-topic list.
- The catalog sorts topics along `TopicItem.pathOrder` (entry-wise operations, elimination, what elimination enables, eigenvalues, then geometry and review) and numbers them by that order; search and category filters still apply. Each topic shows a small `TopicGlyph` drawing of its operation instead of a generic icon. A finished topic carries a check mark with a "Completed" semantics label, a progress line reads "{done} of {total} topics completed", and a "Continue where you left off" card (key `continue-card`) links the last opened topic.
- Practice keeps its curated five-question round first. The completion dialog's "New questions" (key `quiz-new-round`) builds a fresh round with `QuizGenerator`: five questions from four kinds (a 2×2 determinant, the multiplier that zeroes an entry, entry (1,2) of A·A, a 2×2 inverse), every kind once plus one more of a random kind, options and their feedback shuffled together. Each wrong option is one named misconception (e.g. adding the diagonal products, the upside-down ratio, pairing the wrong rows/columns, a forgotten sign). A round is rebuilt from its seed when the language changes.
